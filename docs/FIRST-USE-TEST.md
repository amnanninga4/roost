# First-use test

A twenty-minute session with one person on their own phone. Run it once on the first TestFlight
build and again after the redesign. It is the only test that answers whether the app feels cluttered
to the two people who use it; the expert panel and the density scorecard are instruments, not users.

## Setup

- Tester: the person who has not used the built app yet (Anne first). Observer: the other one.
- The observer reads each task exactly as written and otherwise says nothing. No hints, no
  explanations, no "try holding your finger on it". If the tester asks a question, the answer is
  "what would you try?"
- The phone has TestFlight and a fresh install of the current build, never opened. A pairing code
  minted for the tester (see `RELEASE.md`, "A new phone"), handed over on paper, not read aloud.
- Screen recording on, microphone on (Control Center, Screen Recording, long-press for the mic).
  Ask the tester to say out loud, the whole time, what they are looking for and what they expect to
  happen next.
- Timing starts when the task has been read and stops when the tester says "done" or gives up.

## Tasks

Read one at a time, in this order.

1. Get the app set up so it shows your chores. (The code is on the paper.)
2. Find what you owe today and what is late. Do one of them.
3. Tell me how the two of you are doing this week.
4. You cannot do one of your chores this week. Get it to the other person.
5. Put three things on the shopping list. Mark one as bought.
6. Pick what is for dinner next.
7. Add a project with two steps.
8. One of the chores says something alarming. What is it telling you, and what do you do about it?
9. Change one thing in the app's settings.

## Record, per task

| task | outcome | seconds | wrong taps | hesitations | what they said |
|---|---|---|---|---|---|
| 1 | done / with help / gave up | | | | |
| 2 | | | | | |
| ... | | | | | |

A wrong tap is a tap that did not move them toward the task. A hesitation is a pause of more than
five seconds with no tap. Write quotes down word for word, especially anything starting "where is",
"I thought", or "why".

## After the tasks

Ask, do not explain.

1. On a scale of 1 to 7, how easy was that overall? (1 very hard, 7 very easy)
2. Which screen felt the most crowded? What on it would you remove?
3. What did you expect to find that was not there?
4. What would you tap first tomorrow morning?

## Scoring

- A task with a wrong tap or a hesitation is a finding, whatever the outcome.
- A task done with help, or given up, is a major finding.
- Each finding goes into the redesign brief with its task number and the quote. Against the panel
  report, mark each reviewer prediction confirmed, not seen, or contradicted.

## Rerun

Same sheet, same tasks, after the redesign. If the first tester now knows the app too well, the
other person tests. Compare seconds, wrong taps, and the 1-to-7 score.
